한 줄 핵심 — SSR vs SSG

RAG ≈ SSR

매 요청마다 다시 렌더

질문이 올 때마다 원본을 처음부터 검색해 답을 조립. Next.js의 getServerSideProps처럼 요청 시점에 매번 계산합니다. 느리고, 매번 새로.

LLM Wiki ≈ SSG

미리 컴파일해서 재사용

지식을 한 번 합성해 canonical 페이지로 굳혀둠. next build / getStaticProps처럼 빌드 타임에 미리 만들어 두고 계속 빠르게 재사용합니다.

3계층 = 소스 / 산출물 / 설정

Layer 1 원본 (immutable) raw/
Next.js · public/ + 외부 API 데이터 (읽기 전용) Spring · DB · resources (source of truth, 안 건드림)
Layer 2 컴파일 산출물 entities/ concepts/ …
Next.js · .next/ 빌드 출력 (최적화된 결과) Spring · target/ 컴파일된 Bean
Layer 3 설정 + 매니페스트 SCHEMA · index · log
Next.js · next.config.js + routes-manifest.json Spring · application.yml + ApplicationContext

내가 돌린 빌드 파이프라인 (Orca)

1

정황 파악 orient

SCHEMA.md → index.md → log.md 읽기. 규칙과 기존 상태부터 로드.

Next · 빌드 설정 + 캐시/매니페스트 로드 Spring · @Configuration 스캔
2

소스 읽기 read raw

Orca raw 2개(web + YouTube) 열람. 원본은 절대 수정 안 함.

Next · public/ 소스 파일 read-only Spring · DB record 조회 (dirty 없음)
3

합성 = 컴파일 synthesize

entities/orca.md 생성. frontmatter 9필드 + 출처마커 + wikilink 2개.

Next · 소스 → .next/ 트랜스파일 Spring · @Entity → 컴파일된 Bean
4

매니페스트 갱신 manifest

index.md 총계 8→9, log.md에 빌드 기록 append.

Next · routes-manifest.json 갱신 + 빌드 로그 Spring · Bean 레지스트리 등록
5

검증 lint

계약 위반 0건 확인: 링크·태그·출처·frontmatter·인코딩.

Next · next lint + tsc --noEmit Spring · mvn verify (checkstyle + test)
