# 기획 문서 (Planning)

> 이 폴더는 저장소와 지식 도메인에 대한 **기획·제안·검토 문서**를 모아둔다.
> 작성일: 2026-07-27

## 이 폴더의 성격

기획 문서는 **정본 지식(canonical knowledge)이 아니다.** `docs/`는 [SCHEMA.md](../../SCHEMA.md)가 정의하는 3계층 바깥의 **지원 산출물**이며, 다음 규칙을 따른다.

- `index.md`에 등재하지 않는다.
- `log.md`에 기록하지 않는다. 로그는 정본 지식의 생성·갱신·보관 이력만 다룬다.
- 정본 페이지의 `sources` 항목으로 인용하지 않는다. 근거는 언제나 `raw/` 아래의 원본이어야 한다.
- 정본 페이지 간 연결에 쓰이는 `[[wikilink]]` 대신 **상대경로 Markdown 링크**를 사용한다. 위키링크 최소 개수 규칙에 영향을 주지 않기 위해서다.

기획이 실행되어 실제 지식이 만들어지면, 그 결과물만 `raw/`와 정본 디렉토리에 규칙대로 반영한다.

## 파일명 규칙

```text
NNN-<english-kebab-slug>.md
```

| 요소 | 규칙 |
| --- | --- |
| `NNN` | `001`부터 순차 부여하는 3자리 번호. **한 번 부여하면 절대 바꾸지 않는다.** 문서를 폐기해도 번호는 재사용하지 않는다. |
| `<slug>` | 영문 소문자 + 하이픈(kebab-case). 공백·한글·대문자·언더스코어를 쓰지 않는다. 정본 페이지 명명 규칙과 동일하다. |
| 확장자 | `.md` |
| `000` | 템플릿 전용 예약 번호. 실제 기획에 쓰지 않는다. |

**예시**

```text
000-template.md                        # 템플릿 (예약)
001-insurance-underwriting-domain.md   # 보험 인수심사 도메인 적용 기획
002-schema-lint-automation.md          # (예정) 스키마 검증 자동화
```

번호를 고정하는 이유는 **참조 안정성** 때문이다. 제목이 바뀌어도 "기획 001"은 항상 같은 문서를 가리킨다. 날짜를 파일명에 넣지 않는 이유도 같다. 문서는 개정되지만 파일명은 유지되어야 하므로, 날짜는 frontmatter에서 관리한다.

## Frontmatter 규칙

기획 문서는 아래 필드를 사용한다. 정본 페이지의 frontmatter(`type`, `sources`, `confidence`, `contested`, `contradictions`)와 **의도적으로 다르게** 구성해, 두 계층이 섞이지 않도록 한다.

```yaml
---
title: 문서 제목
created: YYYY-MM-DD
updated: YYYY-MM-DD
status: draft
owner: 담당자
tags: []
related: []
---
```

| 필드 | 설명 |
| --- | --- |
| `title` | 문서 제목 |
| `created` | 최초 작성일. 이후 변경하지 않는다. |
| `updated` | 내용이나 상태가 바뀔 때마다 갱신한다. |
| `status` | 아래 생애주기 값 중 하나 |
| `owner` | 의사결정 책임자. 미정이면 `미정` |
| `tags` | 자유 태그. **`SCHEMA.md`의 정본 태그 택소노미와 무관하며, 등록 절차가 필요 없다.** |
| `related` | 관련 기획 문서의 상대경로 목록 |
| `superseded-by` | (선택) 이 문서를 대체한 기획 문서 경로. `status: superseded`일 때만 사용한다. |

## 상태 생애주기

```text
draft → review → approved → done
                    ↓
              dropped / superseded
```

| 상태 | 의미 |
| --- | --- |
| `draft` | 초안. 검토 요청 전 |
| `review` | 검토 및 논의 중 |
| `approved` | 실행하기로 확정. 아직 미완료 |
| `done` | 실행 완료 |
| `dropped` | 실행하지 않기로 결정. **삭제하지 않고 사유를 남긴 채 보존한다.** |
| `superseded` | 다른 기획 문서로 대체됨. `superseded-by`에 대체 문서를 기록한다. |

폐기된 기획도 지우지 않는다. "왜 그렇게 하지 않기로 했는가"가 나중에 같은 논의를 반복하지 않게 해주는 기록이기 때문이다.

## 새 기획 작성 절차

1. 아래 목록에서 마지막 번호를 확인하고 다음 번호를 정한다.
2. [`000-template.md`](000-template.md)를 복사해 `NNN-<slug>.md`로 저장한다.
3. frontmatter를 채우고 `status: draft`로 시작한다.
4. 템플릿의 모든 `<꺾쇠 괄호>` 자리표시자를 실제 내용으로 교체하거나 삭제한다.
5. 아래 **기획 목록** 표에 한 줄 추가한다.
