# 인수심사 공개 데이터 수집 계획

## 1. 요약

[기획 001](001-insurance-underwriting-domain.md)을 **개인 프로젝트 조건**에서 실행하기 위한 데이터 수집 계획이다. 사내 인수지침서와 재보험사 매뉴얼은 확보할 수 없다는 전제에서 출발한다.

조사 결과, **공개 자료만으로도 인수심사 지식의 상당 부분을 재구성할 수 있다.** 특히 약관·상품요약서·사업방법서가 협회 공시실에 전면 공개되어 있고, 유병자·간편심사 상품은 **인수 요건 자체가 상품요약서에 명시**되어 있다.

가장 큰 제약은 데이터 확보가 아니라 **재배포**다. 이 저장소가 GitHub 공개 상태라면 약관 원문을 그대로 커밋하는 것은 저작물 재배포에 해당한다. 5절의 처리 방식을 먼저 정해야 수집을 시작할 수 있다.

## 2. 배경과 문제

기획 001은 사내 인수지침서, 재보험사 인수 매뉴얼을 원본 계층의 중심으로 상정했다. 그러나 이 프로젝트는 개인 프로젝트이므로 두 자료 모두 접근 경로가 없다.

따라서 다음을 확인해야 했다.

- 공개 자료만으로 의미 있는 인수심사 지식베이스가 성립하는가?
- 성립한다면 무엇을 대체재로 쓸 수 있고, 무엇은 끝내 채울 수 없는가?
- 확보한 자료를 이 저장소에 저장하는 것이 법적으로 문제가 없는가?

## 3. 목표와 비목표

**목표**

- 개인이 합법적으로 접근 가능한 인수심사 관련 공개 소스를 계층별로 정리한다.
- 각 소스를 `raw/`의 어느 디렉토리에 어떤 형태로 보존할지 정한다.
- 저작권 문제를 일으키지 않는 저장 방식을 확정한다.

**비목표**

- 자동 수집 스크립트(크롤러) 구현은 이번 범위가 아니다. 우선 수동 수집으로 1회전을 검증한다.
- 확보 불가능한 자료를 추정이나 전언으로 채우지 않는다. 공백은 공백으로 기록한다.

## 4. 제안 내용

### 4.1 확보 가능성 판정

| 구분 | 항목 | 개인 접근 | 비고 |
| --- | --- | --- | --- |
| 공개 | 약관, 상품요약서, **사업방법서** | 가능 | 협회 공시실에서 직접 다운로드 |
| 공개 | 청약서 계약 전 알릴 의무 질문지 | 가능 | 약관·상품요약서에 포함 |
| 공개 | 유병자·간편심사 상품의 **고지 요건** | 가능 | 상품요약서에 명시. 사실상 공개된 인수기준 |
| 공개 | 분쟁조정례, 판례 | 가능 | 고지의무 판단 기준의 실제 적용 사례 |
| 공개 | 법령, 감독규정 | 가능 | Open API 제공 |
| 무료 | 의학 예후·사망률 문헌 | 가능 | PubMed |
| 무료 | 사망률·언더라이팅 계리 연구 | 가능 | SOA 공개 리포트 |
| **불가** | 회사별 실제 인수기준표(할증률·부담보 테이블) | **불가** | 영업비밀. 대체 불가 |
| **불가** | 재보험사 UW 매뉴얼 | **불가** | 라이선스 계약 대상 |

확보 불가 항목은 **추정하지 않는다.** 정본 페이지에 다룰 경우 `confidence: low`와 함께 "공개 자료로 확인 불가"임을 명시하고, 분쟁조정례·판례에서 역추적 가능한 범위까지만 기술한다.

### 4.3 raw 디렉토리 배치안

```text
raw/
├── policies/       # (신규) 약관, 상품요약서, 사업방법서 발췌
├── disputes/       # (신규) 분쟁조정례, 판례
├── regulations/    # (신규) 법령, 감독규정 조문
├── papers/         # 의학 문헌 (Zotero)
├── articles/       # 계리 리포트, 업계 해설
└── web/            # 웹 캡처 (Web Clipper 경로 보존)
```

신규 3개 디렉토리는 사용 전에 [SCHEMA.md](../../SCHEMA.md)의 디렉토리 표에 등록하고, 정본 `sources`로 인정되는 파일 형식을 함께 정의해야 한다.

## 5. 리스크와 제약

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| **약관 원문 재배포** | 공시 자료는 열람이 자유롭지만 **재배포는 별개**다. GitHub 공개 저장소에 PDF 원문을 커밋하면 저작물 재배포에 해당할 수 있다. | 5.1의 세 방식 중 하나를 **수집 시작 전에** 확정한다. |
| PDF 원문의 대용량화 | Git 저장소가 비대해지고 이력이 무거워진다. | 원문은 `.gitignore` 처리하고 Markdown 발췌만 버전 관리한다. `raw/papers/files/`가 이미 같은 패턴이다. |
| 공개 자료의 시점 노후화 | 약관·법령은 개정된다. 옛 판본을 현행으로 오인할 위험. | raw 레코드에 **공시일·시행일**을 필수 기재하고, 정본 페이지에 적용 시점을 명시한다. |
| 개인정보 유입 | 분쟁조정례·판례에는 실명이 비실명 처리되어 있으나, 수집 과정에서 식별 정보가 섞일 수 있다. | 수집 시 인적사항 제거를 확인한다. 기획 001의 민감정보 금지 조항을 그대로 적용한다. |
| SOA 등 해외 자료의 국내 적용 한계 | 미국 사망률·언더라이팅 관행은 국내와 다르다. | 국내 자료와 교차 검증하고, 차이가 있으면 `contested`로 기록한다. |

### 5.1 저장 방식 선택지

| 방식 | 내용 | 적합한 경우 |
| --- | --- | --- |
| **A. private 저장소 전환** | 저장소를 비공개로 돌리고 원문을 그대로 보존 | 개인 학습·연구 목적. 가장 단순 |
| **B. 메타데이터 + 인용 발췌** | `raw/`에 출처 URL·공시일·조항 번호와 필요한 범위의 인용만 저장 | 저장소를 공개로 유지하고 싶은 경우 |
| **C. 원문 gitignore** | 원문 파일은 로컬에만 두고 커밋하지 않음 | A와 B의 절충 |

**B가 이 스키마와 가장 잘 맞는다.** `sources`는 경로만 요구하고 해석은 정본 페이지에서 수행하므로, 원문 전체가 없어도 계약이 성립한다. 다만 SHA-256 무결성은 "확보한 발췌 본문" 기준이 되므로, 그 범위를 raw 레코드에 명시해야 한다.

## 6. 실행 계획

**파일럿 범위: 유병자·간편심사 상품**

이 범위를 선택한 이유는 다음과 같다.

1. **인수 요건이 상품요약서에 명시적으로 공개**된다. (예: 최근 3개월 내 입원·수술·추가검사 소견 없음, 최근 2년 내 질병·사고 입원·수술 없음, 최근 5년 내 암 진단 없음 형태)
2. 회사별 요건이 미묘하게 달라 `comparisons/`와 `contested` 필드를 실제로 활용할 수 있다.
3. 해당 질환의 의학 문헌으로 "왜 이 기준인가"를 `concepts/`에서 뒷받침할 수 있다.
4. 관련 분쟁조정례가 풍부하다.

- [ ] **5.1의 저장 방식 확정** — 이 결정 전에는 수집을 시작하지 않는다
- [ ] `SCHEMA.md`에 `raw/policies/`, `raw/disputes/`, `raw/regulations/` 등록 및 인정 파일 형식 정의
- [ ] raw 레코드에 공시일·시행일 필드 요구사항 추가
- [ ] Tier 1에서 간편심사 상품 3~5개의 상품요약서 수집 → `raw/policies/`
- [ ] Tier 2에서 고지의무 관련 분쟁조정례 3~5건 수집 → `raw/disputes/`
- [ ] Tier 4에서 대상 질환 1개(예: 당뇨)의 예후 문헌 2~3편 수집 → `raw/papers/`
- [ ] 정본 컴파일 1회전 — `concepts/` 2~3, `comparisons/` 1~2, `queries/` 1~2
- [ ] 린트 및 `index.md`·`log.md` 동기화

목표 규모는 **raw 10~20건 → 정본 5~8페이지**다. 정본 페이지가 3개 미만이면 위키링크 최소 2개 규칙을 만족할 수 없으므로, 한 번에 최소 3페이지 이상을 만들어야 한다.

## 7. 미결정 사항

- **저장소 공개 여부** — 5.1의 A/B/C 중 무엇을 택할 것인가. 나머지 모든 작업의 선행 조건이다.
- **파일럿 대상 질환** — 당뇨, 고혈압, 갑상선 결절 등 중 무엇으로 시작할 것인가.
- **손해보험 포함 여부** — 생명보험만으로 시작할 것인가, 손보(실손·유병자 실손)까지 볼 것인가.
- **수집 자동화 시점** — 수동 1회전 이후 크롤러를 만들 것인가, 계속 수동으로 갈 것인가.
